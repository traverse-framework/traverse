# Traverse v0.13.0

Released 2026-09-25.

Traverse v0.13.0 is a **minor** lockstep crate + npm release. Its throughline
is the discover → execute → trace loop for governed, standalone embedder
apps: Spec `139-embedder-app-state-machine-execution` lands the app command
state machine that drives that loop end to end, and Spec
`140-host-authority-wit-adapters` gives it target-neutral host authorities —
including a real audio-input capability — so the same governed app runs the
same way on native and browser hosts.

## Highlights

### Embedder app state machine and host-connector artifact wiring (Spec 139)

- `app_command` envelopes (embedder-api 1.1.0) and the app state machine
  driver, implemented across Swift, Kotlin, .NET, and web, validated against
  one shared cross-host golden event log (#1502).
- Decision 99: `invoke.input_from` resolves `host_connector_result.<field>`
  at runtime, so a step can consume another host connector's artifact
  without an authority field on the payload; `app validate` rejects an
  unreachable reference.

### Target-neutral host authorities and audio-input (Spec 140)

- WIT host-adapter interfaces make host authorities target-neutral and
  runtime-owned (Decision 97), landing first for `traverse.audio-input`
  (contracts, conformance fixtures, and dispatch/`permission.request`
  wiring in the runtime).
- Real platform adapters: Apple `AVAudioEngine` (Swift, #1499, verified
  against physical microphone hardware) and browser capture/permission
  adapters (web).
- Generic bounded artifact staging shared by runtime, web, and Swift, plus
  audio analysis embedder examples (#1503).

### Native embedder publish pipelines

- New, real CI/CD publish workflows for Maven Central, nuget.org, and the
  Swift `TraverseSwiftHost.xcframework` (#1370/#1371/#1372/#1504) — every
  native embedder now has an automated release path, not just crates.io and
  npm.
- Kotlin `TraverseEmbedder` brought to embedder-api 1.1.0 parity (#1500).
- The Swift xcframework publishes under a dedicated `swift-host-v<version>`
  release tag rather than the shared `v<version>` tag: this repo's
  immutable-releases policy means a GitHub Release can never receive an
  asset after publishing, and a burned tag name can never be reused for a
  release, even after deleting it — the shared tag has no GitHub Release
  object at all, so only a dedicated tag namespace survives a bad first
  attempt.

### Security hardening (Decision 100)

- `RuntimeWasmHost` now runs under explicit fuel and memory limits, and
  fails closed on an out-of-bounds guest response instead of trusting it
  (#1524).
- Backup restore bounds decompressed archive-member size to close a
  decompression-bomb path (#1523/#1531).

### Web fixes

- Preserve event order under reentrant subscriptions, honor pinned and
  zero-major registry version ranges, reject non-string IndexedDB state
  keys, report browser planner truncation accurately, and require matching
  JSON types in browser plans (#1481–#1485).

## Upgrade notes

- Pin `traverse-embedder-web@0.13.0` together with crates at `0.13.0`
  (lockstep, Decision 85).
- Apps using `invoke.input_from` with `host_connector_result.<field>` need
  Spec 139 `0.2.0` / Spec 138 `0.3.0` or later.
- Swift consumers: `Package.swift`'s `TraverseSwiftHost` binary target now
  points at the `swift-host-v0.13.0` release, not a `v0.13.0` GitHub Release
  (which does not exist for this or any future cut — see above).

## Validation

Release preparation must pass these local gates before tagging:

```bash
cargo build --workspace
cargo test --workspace
bash scripts/ci/repository_checks.sh
bash scripts/ci/spec_alignment_check.sh
```

The tagged commit must pass the GitHub `version-guard`, `repository-checks`,
`coverage-gate`, and related required jobs before tag-triggered crates.io /
npm publish, plus the Maven / NuGet / Swift publish workflows introduced in
this release.

## Release steps

Per [the release process](https://github.com/traverse-framework/traverse/blob/main/docs/release-process.md), from a clean `main`
checkout after CI is green:

```bash
bash scripts/ci/bump_version.sh 0.13.0
git push origin main
git push origin v0.13.0
git push origin web-v0.13.0
```

This cut additionally needed a `traverse-registry` crate bump (#1543): the
published `traverse-registry@0.23.0`'s own `traverse-contracts` dependency
range capped below `0.13.0`, so `[patch.crates-io]` could not unify it with
the local workspace crate at the new version.

Then complete the post-cut docs / website checklist in
[the release process](https://github.com/traverse-framework/traverse/blob/main/docs/release-process.md#post-cut-documentation-readmes-and-website).
