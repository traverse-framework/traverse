# Traverse v0.17.0

Released 2026-11-12.

Traverse v0.17.0 is a minor lockstep release for crates and npm. Before 1.0,
a minor bump carries breaking changes, and this one has several:
- every host now runs compatible capabilities through `runtime.wasm`'s
  shared lifecycle;
- guests receive only the submitted input;
- the Rust embedder takes raw JSON text.

It also ships Spec 138 host ceilings and mid-run interruption on native
wasmtime and the web host. Cut with:

```bash
bash scripts/ci/bump_version.sh 0.17.0
```

## Breaking changes

- **Rust embedder input is raw JSON text** (Decision 129, `#1826`, `#1823`).
  `TraverseEmbedderApi::submit` and `start_compatible` take `&str`.
  - Input that isn't JSON is rejected with `invalid_input`.
  - Input JCS cannot represent (a duplicate member name, a lone surrogate,
    an unsafe number) is rejected with `input_not_canonicalizable`, before
    any guest runs.
- **One compatible lifecycle on every host** (Decisions 127–129, Spec 072
  1.1.0, `#1819`, `#1820`, `#1823`).
  - `runtime.wasm` runs the compatible-capability start, stop and kill
    lifecycle, and every host uses it.
  - A capability runs one instance at a time, and instance ids are
    `{capability_id}-compatible-{n}`.
  - `compatible_instance_not_active` replaces `instance_not_found` and
    `instance_not_running`.
  - The started `state_changed` event's `input` is the canonical input.
- **Guests receive only the submitted input** (Decision 124, `#1794`).
  - On Swift, Kotlin and .NET, guests no longer get the
    `{target_id, input}` envelope.
  - A `target_id` that doesn't match the capability is rejected.

## Highlights

- **Model calls stop mid-run on wasmtime and in the browser** (Decisions 104
  and 131, Spec 138 0.16.1 / 0.16.2, `#1582`).
  - Native wasmtime uses epoch interruption, so cancellation and deadlines
    stop `model_execute` and `model_prepare` mid-run.
  - The browser host runs each package's guest in its own reused Worker
    (`modelWorker.js`, shipped in the npm package), which cancellation or the
    deadline terminates.
  - The browser host enforces `maxPackageBytes` / `maxMemoryBytes` /
    `maxFuel`, and fails registration with `host_limit_exceeded`.
- **Native hosts read the model output frame** after `model.execute` through
  `ExactModelMediatedConnector::activated()` (`#1785`).
- **Capability input arrives unchanged** on Swift, Kotlin, .NET (Decision
  126, `#1795`) and the web (Decision 125, `#1802`).
- **`runtime.wasm` is a release asset** on every cut (`runtime-wasm-vX.Y.Z`,
  Decision 123, `#1784`).

## Compatibility

- A web guest trap now fails with `execution_failed` instead of a raw
  `WebAssembly.RuntimeError`.
- Web apps whose bundler does not emit `modelWorker.js` should pass
  `createWorker`. With `createWorker: null`, guests run inline as before.
- No host ABI, guest ABI or bridge ABI version changes. Manifest schemas are
  unchanged.

## Runtime artifact

This release rebuilds the governed `runtime.wasm` with runtime version
`0.17.0` from the Linux-authoritative build. Its digest is in
`runtime/runtime.wasm.sha256` and on the `runtime-wasm-v0.17.0` release.
